# 多分辨率坐标适配方案

本文档记录大话西游2经典版 PC 在多目标客户端分辨率下维护 UI 坐标的长期方案。它只规定设计口径和后续实施顺序，不表示当前已经完成三套分辨率坐标校准。

## 结论

采用混合策略 C：

- 长期资产维护 `game_view` 内归一化 `bbox`。
- 运行时支持 `bbox_by_profile`，profile override 仍然使用 `game_view` 内归一化 bbox。
- 运行时按当前截图识别出的 `game_view` 换算出整张截图坐标系中的整数像素 bbox。
- 如果后续确实需要性能优化，可以缓存 profile 下的像素 bbox；缓存不是事实源，不能替代模板 bbox。

不把固定像素坐标作为主方案。固定像素坐标读取最快，但它必须绑定某一个具体坐标系；窗口标题栏、边框、截图裁剪、`game_view` 偏移或 4:3/16:9 布局差异都会让它失效。

bbox 换算本身不是性能瓶颈。一次换算只有少量乘法、加法和取整，成本远低于截图读取、hash 匹配和 OCR。

## 术语

- 目标客户端分辨率：游戏设置中选择的画面分辨率，例如 `800x600`、`1024x768`、`1366x768`。
- 整张截图分辨率：截图文件实际宽高，可能包含 Windows 标题栏、边框或其他非游戏区域。
- `game_view`：`detect_game_view()` 识别出的游戏画面区域，是模板 bbox 的归一化基准。
- Agent Rows 点击区域：最终输出给外部 agent 的整张截图坐标系整数像素 bbox。

运行时 profile 只按实际截图或 `game_view` 尺寸判定，不直接读取游戏设置中的目标客户端分辨率。当前已确认游戏内 `1024x768` 设置生成的截图实际尺寸为 `1024x720`，因此运行时登记为 `fixed_window_1024x720`；文档或样本备注可以保留“来源设置为 1024x768”，但模板匹配、bbox_by_profile 和置信度计算都必须使用实际截图尺寸 `1024x720`。

三种目标客户端分辨率暂不直接定义为运行时 profile 标签。后续实现时，应再映射到当前 `game.json` 的 `supported_aspect_ratios` / `supported_windows` 体系，避免形成两套命名口径。

## 坐标链路

坐标链路固定为：

```text
真实截图 -> detect_game_view() -> game_view 内归一化 bbox/profile bbox -> 当前整图像素 bbox -> Agent Rows 名称@[left, top, right, bottom]
```

模板资产中的 bbox 表达“这个 UI 区域位于 game_view 的哪个比例区域”。运行时会把 bbox 换算为整张截图坐标系中的像素 bbox，并直接作为点击区域输出。

Agent Rows 外部输出保持扁平 index/value JSON，不新增结构化 `action_targets`：

```json
{
  "400": "水晶宫@[397, 729, 534, 772]",
  "401": "水晶宫@[51, 207, 191, 247];爱你万年@[205, 207, 346, 247]"
}
```

## 资产规则

`anchors`、`elements`、`static_outputs` 的默认 `bbox` 都使用 `game_view` 内归一化坐标。

如果发现不同目标客户端分辨率下 UI 布局不同，可以使用类似下面的覆盖结构：

```json
{
  "id": "selected_server_slot",
  "type": "button_slot",
  "semantic_role": "selected_server_slot",
  "value": "",
  "bbox": [0.477, 0.778, 0.547, 0.811],
  "bbox_by_profile": {
    "some_future_profile_label": [0.480, 0.780, 0.550, 0.814]
  }
}
```

`bbox_by_profile` 里的值仍然是 `game_view` 内归一化 bbox，不是像素坐标，也不是整张截图比例坐标。

固定像素 bbox 可以作为校准产物或缓存存在。若未来记录像素 bbox，必须明确它属于哪个坐标系，例如 `game_view` 内坐标或整张截图坐标。

## 缓存策略

默认不需要缓存 bbox 换算结果。若后续实测需要缓存，缓存键至少包含：

- `template_id`
- 目标客户端分辨率或运行时 profile
- `game_view.bbox` 或能代表 `game_view` 的 hash
- 模板版本

缓存失效条件至少包括：

- 窗口尺寸变化
- `game_view.bbox` 变化
- 模板版本变化
- profile 或目标客户端分辨率变化

缓存值可以是 `game_view` 内像素 bbox，也可以是最终整张截图像素 bbox，但必须标明坐标系。缓存不是事实源；事实源仍然是 bbox / `bbox_by_profile`。

## server_select 优先级

第一批多分辨率校准对象是 `server_select`。

优先校准以下槽位：

- `selected_server_slot`
- `account_server_slot_*`
- `server_confirm_button`

输出规则保持不变：

- `400 selected_server`：`服务器名@[left, top, right, bottom]`
- `401 account_servers`：`服务器名@[left, top, right, bottom];服务器名@[left, top, right, bottom]`
- `3 server_name`：兼容字段，跟随 `400`

没有对应目标客户端分辨率的真实截图或人工标注结果前，不得声称该分辨率坐标已校准，也不得从当前样本简单线性推断后写入模板资产。

## 后续实施顺序

1. 采集 `800x600`、`1024x768`、`1366x768` 三种目标客户端分辨率下的真实 `server_select` 截图。
2. 确认每张截图的整张截图尺寸、`game_view.bbox`、目标客户端分辨率和当前运行时 aspect/profile 命中结果。
3. 人工标注 `selected_server_slot`、`account_server_slot_*`、`server_confirm_button` 的可点击区域。
4. 如果默认 bbox 能覆盖三种分辨率，继续使用默认 bbox。
5. 如果某个目标客户端分辨率布局明显不同，优先使用 `bbox_by_profile`；差异过大时再拆分模板变体。
6. 增加 schema 和换算测试，确认 profile 覆盖优先级、fallback 和最终 Agent Rows bbox。

## 验收标准

- 文档和实现都不把固定像素坐标作为唯一事实源。
- 三种目标客户端分辨率不被误认为整张截图分辨率。
- 所有模板 bbox/profile override 都基于 `game_view` 归一化坐标。
- 没有真实样本或人工标注前，不写入伪校准坐标。
- 不引入 OCR，不新增结构化 `action_targets`，不改变 Agent Rows 外部 JSON。
