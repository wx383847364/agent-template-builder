# 模板资产与演化规则

这份文档记录模板资产如何长期增长。它关注资产可信度，不关注某个功能是否“完成”。

## 模板包结构

当前模板包位于：

```text
configs/games/dhxy2_classic_pc/
  game.json
  templates/*.json
  vocab/*.txt
samples/dhxy2_classic_pc/
  screenshots/
  expected/
```

## 样本命名

原始实时截图池中的文件名可以是时间戳或固定格式，只用于追踪和排序，不参与模板识别。精选校准样本按模板或屏幕类型命名：

```text
samples/dhxy2_classic_pc/screenshots/<template_id>__<case>.png
samples/dhxy2_classic_pc/screenshots/<screen_type>__<case>.png
```

同一个模板可以保留多张样本，用于覆盖分辨率、UI 状态和弹窗组合。

真实截图采集时优先使用固定窗口，当前首批校准路径采用：

```text
samples/dhxy2_classic_pc/screenshots/main_world__baseline.png
samples/dhxy2_classic_pc/screenshots/npc_dialog__baseline.png
samples/dhxy2_classic_pc/screenshots/blocking_modal__baseline.png
```

expected 只维护一份最终 JSON：

```text
samples/dhxy2_classic_pc/expected/final_expected.json
```

这份文件用 `field_dictionary` 维护全局字段序号，序号只增不改。`cases` 中每个截图样本只填写实际能读到的 `field_values`，格式为 `field_no` 加 `value`；不要求每张图输出全量字段。新增字段时追加新的序号，例如当前 `1` 是账号名称、`2` 是密码、`3` 是服务器名称。

覆盖率报告既支持旧式 `<template_id>__<case>.json` / `<screen_type>__<case>.json`，也支持从 `final_expected.json` 的 `cases[].template_id` 或 `cases[].screen_type` 统计每个模板是否已有 expected 基线。

如果 `cases[].screenshot` 指向的截图文件存在，覆盖率报告也会按该 case 的模板统计截图样本。这样时间戳截图可以先保留原始文件名，再通过 expected manifest 进入校准样本口径。

## BBox 规则

- `bbox` 使用 `[left, top, right, bottom]`。
- 坐标单位是屏幕归一化比例，范围为 `0..1`。
- 运行时根据截图宽高换算成像素坐标。
- 新增或调整 bbox 时，优先用真实固定窗口截图校准。

## Anchor 与 Hash 规则

- `anchors` 用于稳定识别屏幕模板。
- 有 `expected_hash` 的 anchor 才算可度量 anchor。
- 没有真实样本前可以先保留布局锚点，但必须在覆盖率报告中暴露缺口。
- hash 应来自本地固定窗口截图，不应直接使用公开参考图。

## OCR 区域规则

- 只有动态文本区域设置 `ocr_required: true`。
- 固定按钮、标题、图标和布局区域优先用模板识别。
- OCR 结果必须通过 `Evidence` 记录来源区域。
- 新增 OCR 区域时，需要同步考虑 expected JSON 中的预期输出。

## 覆盖率口径

使用下面命令查看模板资产缺口：

```bash
agent-template-builder-template-coverage
```

一个模板至少需要持续补齐：

- 模板 JSON。
- 真实截图样本。
- expected JSON。
- 可度量 anchor/hash。
- 必要的 OCR 区域。

覆盖率报告用于指导下一步采样和校准，不作为硬性发布门禁。
