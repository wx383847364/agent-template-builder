# 模板资产与演化规则

这份文档记录模板资产如何长期增长。它关注资产可信度，不关注某个功能是否“完成”。

## 模板包结构

当前模板包位于：

```text
configs/games/dhxy2_classic_pc/
  game.json
  templates/*.json
  vocab/*.txt
samples/dhxy2_classic_pc/
  screenshots/
  expected/
```

## 样本命名

原始实时截图池中的文件名可以是时间戳或固定格式，只用于追踪和排序，不参与模板识别。精选校准样本按模板或屏幕类型命名：

```text
samples/dhxy2_classic_pc/screenshots/<template_id>__<case>.png
samples/dhxy2_classic_pc/screenshots/<screen_type>__<case>.png
```

同一个模板可以保留多张样本，用于覆盖分辨率、UI 状态和弹窗组合。

真实截图采集时优先使用固定窗口，当前首批校准路径采用：

```text
samples/dhxy2_classic_pc/screenshots/main_world__baseline.png
samples/dhxy2_classic_pc/screenshots/npc_dialog__baseline.png
samples/dhxy2_classic_pc/screenshots/blocking_modal__baseline.png
```

legacy 参考池已纳入首批 anchor/hash 校准样本：

```text
samples/dhxy2_classic_pc/screenshots/main_world__legacy_game1.png
samples/dhxy2_classic_pc/screenshots/battle__legacy_battle1.png
samples/dhxy2_classic_pc/screenshots/login_waterfall__legacy_login1.png
samples/dhxy2_classic_pc/screenshots/system_panel__legacy_character_attributes1.png
```

expected 只维护一份最终 JSON：

```text
samples/dhxy2_classic_pc/expected/final_expected.json
```

这份文件用 `field_dictionary` 维护全局字段序号，序号只增不改。`cases` 中每个截图样本只填写实际能读到的 `field_values`，格式为 `field_no` 加 `value`；不要求每张图输出全量字段。新增字段时追加新的序号，例如当前 `1` 是账号名称、`2` 是密码、`3` 是服务器名称。

覆盖率报告既支持旧式 `<template_id>__<case>.json` / `<screen_type>__<case>.json`，也支持从 `final_expected.json` 的 `cases[].template_id` 或 `cases[].screen_type` 统计每个模板是否已有 expected 基线。

如果 `cases[].screenshot` 指向的截图文件存在，覆盖率报告也会按该 case 的模板统计截图样本。这样时间戳截图可以先保留原始文件名，再通过 expected manifest 进入校准样本口径。

## BBox 规则

- `bbox` 使用 `[left, top, right, bottom]`。
- 坐标单位是屏幕归一化比例，范围为 `0..1`。
- 运行时根据截图宽高换算成像素坐标。
- 新增或调整 bbox 时，优先用真实固定窗口截图校准。

## Anchor 与 Hash 规则

- `anchors` 用于稳定识别屏幕模板。
- 有 `expected_hash` 的 anchor 才算可度量 anchor。
- 没有真实样本前可以先保留布局锚点，但必须在覆盖率报告中暴露缺口。
- hash 应来自本地固定窗口截图，不应直接使用公开参考图。

## OCR 区域规则

- 只有动态文本区域设置 `ocr_required: true`。
- 固定按钮、标题、图标和布局区域优先用模板识别。
- OCR 结果必须通过 `Evidence` 记录来源区域。
- 新增 OCR 区域时，需要同步考虑 expected JSON 中的预期输出。

## 覆盖率口径

使用下面命令查看模板资产缺口：

```bash
agent-template-builder-template-coverage
```

一个模板至少需要持续补齐：

- 模板 JSON。
- 真实截图样本。
- expected JSON。
- 可度量 anchor/hash。
- 必要的 OCR 区域。

覆盖率报告用于指导下一步采样和校准，不作为硬性发布门禁。

## Agent Rows 运行时字段配置

运行时固定 index/value rows 的字段定义不再从 expected 资产读取。`samples/dhxy2_classic_pc/expected/final_expected.json` 中的 `field_dictionary` 只保留为 expected/回归说明资产；稳定运行时字段配置位于：

```text
agent_fields.json
```

新增或调整稳定 rows 字段时，应优先更新 `agent_fields.json` 中的 `fields`、`mappings` 和 `reserved_ranges`，再补充 expected 样本覆盖。

字段编号区间、字段状态和发布/废弃规则见 [AgentRows字段编号规划.md](AgentRows字段编号规划.md)。expected 中的 `field_dictionary` 只作为历史兼容说明，不自动发布为运行时 Agent Rows 字段。
## 模板静态导出层

模板可以通过 `static_outputs` 定义识别后直接注入 `AgentData.elements[]` 的固定内容。适用范围包括固定 UI 文案、固定按钮、固定槽位和后续可用于点击坐标绑定的布局点。

每条 `static_outputs` 至少包含：

- `id`：模板内唯一标识。
- `type`：元素类型，例如 `button`、`button_slot`。
- `semantic_role`：导出或绑定使用的语义角色。
- `text` 或 `value`：固定文本或占位值；纯槽位可以使用空字符串。
- `bbox`：可选；存在时使用归一化屏幕坐标，运行时换算为截图坐标系 bbox。

维护规则：

- 固定内容优先放在模板静态层，不要伪装成 OCR 区域。
- 动态内容仍保留在 `elements` 中，并用 `ocr_required: true` 标记，后续再接 OCR 或人工替代输入。
- 需要点击坐标的槽位应以可点击中心点为准校准 bbox。
- `static_outputs` 注入后的 evidence source 是 `template_static`，用于与 `template` 匹配证据和 `ocr` 文本证据区分。

`server_select` 当前使用静态层定义账号服务器按钮槽位、当前选中服务器槽位和进入游戏按钮；服务器名本身仍来自后续 OCR 或人工替代输入。

## 多分辨率坐标适配

多目标客户端分辨率下的 bbox、静态槽位和点击坐标维护规则见 [多分辨率坐标适配方案.md](多分辨率坐标适配方案.md)。

长期资产以 `game_view` 内归一化 bbox 为事实源；固定像素坐标只能作为校准产物或缓存，不能替代模板 bbox。

旧文档中“运行时按截图尺寸换算 bbox”的表述应按当前坐标链路理解为：先通过 `detect_game_view()` 得到 `game_view`，再把 `game_view` 内归一化 bbox 映射回整张截图坐标系。
