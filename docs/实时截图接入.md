# 实时截图接入

这份文档记录“实时截图目录 -> 模板匹配 -> AgentData JSON”的最小闭环。

## 目录职责

原始实时截图池保存采集器持续写入的图片。文件名可以是时间戳、自增编号或其他固定格式，只用于追踪、回放和排序，不用于判断屏幕类型。

```text
references/dhxy2_public/legacy/
runtime/screenshots/
```

精选校准样本保存从原始池中挑出的代表截图，用于人工确认、anchor/hash 校准和 expected 回归。

```text
samples/dhxy2_classic_pc/screenshots/
samples/dhxy2_classic_pc/expected/final_expected.json
samples/dhxy2_classic_pc/calibration_candidates.json
```

实时识别不依赖 expected；expected 用于校准和回归。没有人工确认 OCR 文本前，不填写假的 `field_values`。

## 命令入口

分析单张截图并输出完整 `AgentData`：

```bash
.venv/bin/agent-template-builder-analyze <screenshot.png>
```

分析目录中修改时间最新的截图，输出摘要：

```bash
.venv/bin/agent-template-builder-analyze-screenshots <screenshots_dir> --latest
```

分析目录中修改时间最新的截图，输出完整 `AgentData`：

```bash
.venv/bin/agent-template-builder-analyze-screenshots <screenshots_dir> --latest --agent-data
```

批量分析目录，输出每张截图的 `screen.type`、`template_id`、`confidence`、分辨率和 `raw.match`：

```bash
.venv/bin/agent-template-builder-analyze-screenshots <screenshots_dir>
```

批量分析目录并按 JSON Lines 输出，便于另一个 agent 或日志管道逐行消费：

```bash
.venv/bin/agent-template-builder-analyze-screenshots <screenshots_dir> --jsonl
```

## 识别原则

- 截图文件名不参与模板识别。
- 屏幕类型判断依赖模板、可度量 anchor/hash 和布局信息。
- OCR 只读取模板中 `ocr_required: true` 的动态区域。
- bbox 继续使用归一化屏幕比例，运行时按截图分辨率换算。

## 当前限制

`dhxy2_classic_pc` 已为主世界、战斗、登录瀑布和人物属性类系统面板补齐首批真实 `expected_hash`。目录分析会在 `raw.match.measurable_template_count` 中报告当前可度量模板数量；如果存在可度量模板但没有任何 anchor 匹配，matcher 会以 `no_anchor_hash_match` 回退主世界，避免高优先级模板仅凭优先级误胜出。

这意味着目录分析闭环已经可用，但模板类型准确率仍取决于继续从真实截图补齐更多 anchor/hash。当前 legacy 图包含窗口边框，部分分辨率和宽高比不在正式固定窗口配置内，置信度会受到 viewport 评分惩罚。

## legacy 候选池

`references/dhxy2_public/legacy` 当前有一批真实或历史截图，可作为第一批校准候选入口。候选映射记录在：

```text
samples/dhxy2_classic_pc/calibration_candidates.json
```

候选映射只表达“这张图可能对应哪个模板”，不代表 expected 已可信。将候选图纳入回归前，需要人工确认截图类别、稳定 anchor 区域和必要 OCR 字段。

## 本地游戏路径配置

实时截图目录优先从本地配置和已知游戏目录中检索。个人机器路径写入 `configs/local.json`，该文件已加入 `.gitignore`，避免把本地磁盘路径提交到仓库。仓库只提交 `configs/local.example.json` 作为字段示例。

当前支持的配置字段：

```json
{
  "games": {
    "dhxy2_classic_pc": {
      "install_dir": "G:/大话/大话西游2_经典版",
      "screenshot_dir": "G:/大话/大话西游2_经典版/screen"
    }
  }
}
```

截图目录解析顺序：

1. 环境变量 `AGENT_TEMPLATE_BUILDER_SCREENSHOT_DIR`
2. `configs/local.json` 中的 `games.dhxy2_classic_pc.screenshot_dir`
3. 已知默认路径 `G:/大话/大话西游2_经典版/screen`
4. 项目样本目录 `samples/dhxy2_classic_pc/screenshots`

因此下面的命令会自动分析默认截图目录中修改时间最新的图片：

```powershell
.\.venv\Scripts\python.exe -m agent_template_builder.pipeline.analyze_screenshots --latest
```

仍然可以显式传入目录覆盖默认检索：

```powershell
.\.venv\Scripts\python.exe -m agent_template_builder.pipeline.analyze_screenshots G:\大话\大话西游2_经典版\screen --latest
```

## 游戏画面 ROI

Windows 窗口截图会包含标题栏、标签栏和窗口边框。运行时会先定位 `game_view`，再以 `game_view` 为基准计算模板 bbox 和 anchor/hash；输出元素 bbox 仍映射回整张截图的像素坐标，便于后续点击或证据回放。

当前 `server_select` 和 `character_select` 已使用本地窗口截图完成首批 ROI-relative anchor/hash 校准。离线标注时使用 [目标模式标注提示词.md](目标模式标注提示词.md)，不要把视觉模型调用放入运行时主链路。
